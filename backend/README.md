# Supplement Tracker — Backend

FastAPI + SQLAlchemy + PostgreSQL REST API for tracking supplement restock timing.

## Setup

### 1. Start Postgres (via Docker)

```bash
cd backend
docker compose up -d
```

This starts a local Postgres instance on `localhost:5432` with a persistent volume, matching what you'd get from a managed provider like Render or Railway.

### 2. Configure environment

```bash
cp .env.example .env
```

The default values in `.env.example` already match `docker-compose.yml`, so no edits are needed for local dev. When you deploy, replace `DATABASE_URL` with your managed provider's connection string — no code changes required.

### 3. Install dependencies

```bash
python3 -m venv venv
source venv/bin/activate        # on Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 4. Run migrations

```bash
alembic upgrade head
```

This creates the `supplements` and `sources` tables. Whenever you change `models.py`, generate a new migration with:

```bash
alembic revision --autogenerate -m "describe your change"
alembic upgrade head
```

Always review autogenerated migrations before running them — Alembic is good but not perfect at detecting every change.

### 5. Run the API

```bash
uvicorn main:app --reload
```

- API: http://127.0.0.1:8000
- Interactive docs (Swagger UI): http://127.0.0.1:8000/docs
- Alt docs (ReDoc): http://127.0.0.1:8000/redoc

## Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/supplements` | List all supplements with computed days_remaining/status |
| POST | `/supplements` | Create a new supplement (optionally with nested `sources`) |
| GET | `/supplements/{id}` | Get one supplement |
| PUT | `/supplements/{id}` | Partially update a supplement |
| DELETE | `/supplements/{id}` | Delete a supplement (cascades to its sources) |
| POST | `/supplements/{id}/restock` | Reset start_date to today (optionally pass `?new_total_doses=N`) |
| POST | `/supplements/{id}/sources` | Add a restock source (store name and/or link) |
| DELETE | `/sources/{id}` | Remove a restock source |

## File layout

- `database.py` — SQLAlchemy engine/session setup, reads `DATABASE_URL` from `.env`
- `models.py` — ORM table definitions (`Supplement`, `Source`)
- `schemas.py` — Pydantic request/response contracts
- `crud.py` — DB read/write functions
- `logic.py` — pure date-math (days_remaining, restock_date, status) — unit test this directly
- `main.py` — FastAPI app and route handlers
- `alembic/` — schema migrations (see `alembic/versions/`)
- `docker-compose.yml` — local Postgres for development

## Notes on the Postgres migration

This project originally used SQLite with `Base.metadata.create_all()` to auto-create tables. It now uses Postgres with Alembic-managed migrations — the more common pattern in real teams, since it tracks schema history and supports rolling changes forward/backward safely instead of only ever creating tables from scratch.
